# Delivery — AUDIO.Sampler

How it is built, tested and shipped, and where it lands.

| Step | What happens | Automated? |
|---|---|---|
| Build | `./build.sh` → `npm install` once (Babel), then `node build.mjs`: tests first, then `dist/app.js`, `dist/gui.js`, `dist/fx.js`, `dist/precache.json`. | no — run by whoever edits a source |
| Commit | Sources **and** the three tracked bundles together. `npm run check` says which bundle is stale. | no |
| Test (CI) | `.github/workflows/test.yml` in this repo: on push and pull request, `npm ci`, `npm test` (floor runner + `padmeta.test.mjs`), `npm run check`. Full history (`fetch-depth: 0`) because the stamp reads the last source commit. It commits nothing. | yes (added 2026-10-30; first run happens on the next push) |
| Push | Own repo `https://github.com/LikeDotAudio/APK.softapp.AUDIO.Sampler.git`, submodule of APK.audio at `PODS/POD.THIN/Softapps/AUDIO/AUDIO.Sampler`; the monorepo's `.apk.scripts/deploy_all.py` pushes every submodule and bumps pointers. | by hand |
| Site | The monorepo's `.github/workflows/ci.yml` runs `PODS/POD.THIN/WEB.Frontend-Assets/.apk.scripts/deploy.py` on push to `main`: one FTPS session uploads the checkout. `PODS/POD.THIN/OS/system/published.set.json` names what of this folder is carried (`index.html`, `manifest.json`, `sw.js`, `dist/app.js`, `dist/gui.js`, `dist/fx.js`, `libControl/Effects`, `libControl/SoundSynth`, React from `vendor/`, `ICON and LOGO`, the eight kits) and what is dropped (`dist/precache.json`, the two demo tracks; `vendor/mqtt.min.js` was dropped too and is now deleted from this repo). It builds and tests nothing: the bytes on the site are the committed bytes. | yes, on push |
| Bench image | `PODS/POD.THIN/WEB.Frontend-Assets/Docker/Dockerfile` copies the whole Softapps tree into nginx (`/srv/www/Softapps`, alias `/APK:Softapps`); the OS sound pages on a bench load `dist/*.js` from there. `DATABASE.server.SQL` proxies `/APK:Softapps/` to it (PLAN-3421.01). Rebuild with `up-stack.sh WEB.Frontend-Assets`. | no |

**Live**: <https://apk.audio/APK%3ASoftapps/AUDIO/AUDIO.Sampler/index.html> and
<https://Sampler.Like.audio/> (both HTTP 200 on 2026-10-30). The smoke result is on the
[wiki home](../README.md).

**Not automated**: compiling the bundles (CI only checks they match), registering the service worker
on the published origin in a real browser (the old `check_sampler_service_worker.mjs` did this with
puppeteer; it went with the 2026-09-10 stack split and is not in this suite), rebuilding the bench
image, pushing.

## Delivered from the 2026-10-30 audit

- **Bundle export contract** — `exports.json` declares the `window.*` names `dist/fx.js` (40, plus the nine plugin ids the OS desk checks), `dist/gui.js` (the eight faceplates) and `dist/app.js` (`Pads`, `Sequencer`, `oaBusUrl`, the topic module, plus everything fx and gui give) must define for APK:OS (`OS/system/sound.modules.json`; names measured against `OS/Mixer/dsp/*`, `OS/Midi/pads`, `OS/Midi/sequencer`). `test/exports.test.mjs` boots each committed bundle alone in a fresh fake window (`test/bootScripts.mjs`) and asserts every name, the plugins, gui-on-fx as the mixer page loads it, and no stray entries. This repo is the supplier of the OS sound pages (host, mixer, midi); verified with `npm test`.
- **Bundle API version** — `package.json` 1.0.0 → 1.1.0 (the contract is the API), equal to `exports.json` `version` (tested). `build.mjs` writes it into each bundle as `window.OA_FX_API` / `OA_GUI_API` / `OA_APP_API`, and `exports.json` is part of every bundle's stamp, so a version bump without a rebuild fails `npm run check`. Semver rule written in `exports.json` and ARCHITECTURE.md. The OS side (pin on the major) is handed off to APK:OS.
- **One topic module** — `libControl/App/oaTopics.js` (`window.oaTopics`: `drumKitSample`, `drumKitEq`, `DRUM_KIT_EQ_ALL`, `parseDrumKitEq`, `DRUM_SETS`, `SOUND_FAVORITES`, `seq(label, key)`) replaces the 15 hand-built strings in `useSeqState.js`, `useSamplerState.js`, `useSeqMenus.js`, `useSamplerSets.js`, `useSoundBrowseState.js` and `oaEqBridge.js`. Same wire topics; `test/eq.test.mjs` and the new payload test pass.
- **Bus payload schemas + test** — `window.OA_BUS_PAYLOADS` / `oaBusPayloadProblem(topic, payload)` in `oaTopics.js` declare every payload (table in ARCHITECTURE.md). `test/payloads.test.mjs` dials a fake broker through the real `mqttBus.js`, drives the sequencer, pads, sets and sound-browser hooks through their setters, holds every publish to its shape and fails if a declared shape is never exercised. It found a real bug: the Pads' `kitMeta` JSON.parsed an already-parsed bus value, so a kit published by another client never reached "restore" — fixed in `useSamplerState.js`, with a regression test (fails on the old code).
- **Vendored versions recorded** — `vendor/VENDOR.json`: mqtt.js 5.10.1, React/ReactDOM 18.3.1, with source URL and sha256; `test/manifests.test.mjs` fails on an unrecorded file or changed bytes. Compared 2026-10-30: `OS/vendor/mqtt.min.js` and `OS/DataBus/vendor/mqtt.min.js` are byte-identical; WEB.Frontend-Assets carries mqtt.js 5.10.1 (different minification) and React 18.3.1 development builds.
- **Shared bus helper adopted (W09)** — `mqttBus.js` now dials through `window.APKBus` (`/FrontEnd/shared/apk-bus.js`, WEB.Frontend-Assets: the one vendored mqtt.js, failover to the saved override / shell broker / same-origin `/mqtt`) when it is on the page or served; uses `window.mqtt` directly when the OS sound agent supplied it (framed on the desk); falls back to `./vendor/mqtt.min.js` only where the helper is not served (the standalone host) — superseded by WS-05 below: that fallback and the file are gone. Own session (`shareShell: false`) as before; one packet matching two of our filters is delivered once. Tested in `test/payloads.test.mjs` with a fake APKBus. Reversible: deleting the helper branch restores the old path.
- **sound-agent.js dependency made explicit** — declared in `exports.json` `consumes` as an APK:OS-supplied endpoint and tested against `index.html` (`test/exports.test.mjs`), documented in ARCHITECTURE.md. Kept by design: the URL stays relative (`../../../APK:OS/…`), because it follows the APK:Softapps-beside-APK:OS layout wherever the portal mounts it, and the alternative (OS injecting it when it frames the page) is APK:OS's change, not this repo's.
- **Dead `display.json` topic removed** — `APK.audio/Gui/Display/Sampler` (nothing published on it; nothing in POD.THIN read it) is gone; KNOWN_ISSUES updated.
- **Page loads headless** — `test/page.test.mjs` runs `index.html`'s own `<script src>` chain in document order (React UMD replaced by the fake, the OS files in `consumes` skipped) and fails on a script error, on a page that does not render exactly once into `#root`, or on an App that throws on its first render. Part of `npm test`, so CI (`.github/workflows/test.yml`) runs it on push. The deployed-site smoke (`.apk.scripts/smoke.py`) is the root's and is handed off.

Tested: `npm test` (floor runner: 324 cases, 59 suites, 24 files, all pass; floor raised with `--set-baseline`), `node build.mjs` (tests first, then the three bundles) and `npm run check` (all three up to date).

### From the SDK/contracts audit (2026-10-30)

- **WS-05 own mqtt.js and a port-guess broker URL** — `vendor/mqtt.min.js` deleted (and its `VENDOR.json` entry); `mqttBus.js` reaches a broker only through the shared `window.APKBus` helper, which owns the shell's seed order (`oa_bus_url`, the shell's broker, the gateway `/mqtt` door; null on a public origin). `oaBusUrl` no longer guesses `ws(s)://<host>:9001` and no longer gates on `oaIsLocalOrigin` (a gateway hostname failed it). The OS sound agent's named port client still works directly. `test/payloads.test.mjs` adds: no broker named → the helper is loaded and chooses (no `brokerUrl`); helper not served → no bus and no mqtt.js fetched. `grep -E ':9001|vendor/mqtt.min.js'` over the sources is empty. (This change was found uncommitted in the tree, already written to the guide's recipe; reviewed, tested and committed here.)
- **WS-06 gui-state topics pinned to the contract** — `test/contracts.test.mjs` checks every `oaTopics` topic against `Topics.gui.state({stateRoot, path})` and `Topics.parse` (kind `guiState`, root in `GUI_STATE_ROOTS`) from `contracts/generated/web/apk-contracts.mjs`, and that a sequencer label becomes one grammar segment. Skipped with its reason in a standalone clone.
- **WS-07 brand accent from brand.json** — `contracts/tokens/brand.json` vendored as `tokens/brand.json` (byte-identical, tested; also held by the monorepo's `webtokens` lane). `LensesView.jsx`'s canvas pitch line and label now use `window.oaAccent()`; `SeqControls.jsx`'s swing-table highlight uses `oaAccentRgba(0, 0.15)`; `oaAccentRgba`'s fallback derives from `OA_ACCENT_RGB`. The literals a static file must carry (`oaTheme.js` default, `index.html` `--accent` / `--accent-rgb` / theme-color, `manifest.json` theme_color, the picker's default swatch) are held to brand.json by `test/contracts.test.mjs`, which also fails if any other source names the accent.
- **Schema citations repointed** (handoff from S01) — `oaDeepScanner.js`, `extract_note_root_beat_map.py` and `test/padmeta.test.mjs` now cite PROCESSOR.SampleAnalyzer `schema/peak.schema.json` instead of the moved `analyzerPeakSchema.json`.

Tested: `npm test` (332 cases / 61 suites / 25 files, floor raised), `node build.mjs`, `npm run check`.
